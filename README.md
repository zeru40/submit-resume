# 求职投递助手 / Career Desk

Windows 单用户本地桌面工具，无软件注册和登录界面。参考相邻 `boss-hr-desktop-main` 的桌面容器、浏览器所属线程、协作式暂停和动作账本设计，重新实现求职者端数据模型与流程。数据不与招聘端项目共享。

## 启动

已安装 Python 3.11+ 和 Microsoft Edge 时：

1. 首次双击 `install.bat` 安装依赖。
2. 双击 `start.bat` 打开桌面窗口。
3. 若桌面 WebView 不可用，程序回退到默认浏览器。

```powershell
.\.venv\Scripts\python.exe app.py
# 使用默认浏览器打开管理界面
.\.venv\Scripts\python.exe app.py --browser
# 仅启动本地服务，默认地址 http://127.0.0.1:8188
.\.venv\Scripts\python.exe app.py --no-open
```

程序仅绑定 `127.0.0.1`，自动寻找可用端口，并在 Windows 使用单实例互斥。招聘平台窗口使用本机 Microsoft Edge 的普通启动方式，再通过仅监听本机的 CDP 连接；请先安装 Microsoft Edge。启动时直接传入平台网址，不添加 `--no-sandbox` 或隐藏自动化的开关。

## 使用流程

1. **我的简历**：导入 PDF、DOCX 或 TXT，自动提取文字并打开解析预览。支持从明确字段识别姓名、所在城市、学历和原文技能；不推断未注明的期望城市、薪资和工作年限。扫描 PDF 没有文字时会提示，不会保存空简历。单份最大 15 MB，PDF 最多 30 页。
2. **求职方案**：填写岗位关键词、城市、平台城市代码、薪资下限、技能和排除词，选择简历版本。薪资单位为月薪 K。城市代码从平台搜索地址取得，与期望城市分开保存。
3. **工作台**：选择平台，点击“打开平台”，在官方页面登录求职账号，然后点击“检查状态”。人工登录时只启动普通 Edge，不建立 Playwright 连接、不读取网页、不重复导航；完成登录后再接管浏览器。已有登录标签时保留当前二维码与输入内容。软件自身无需登录。验证码与安全验证由人工处理。
4. 先运行 **仅搜索岗位**，在 **岗位与投递** 检查详情与匹配原因。
5. 点击 **开始自动投递**，或在岗位列表勾选记录后投递。可配置单轮数量和操作间隔。
6. 遇到“结果待核验”，打开平台检查实际结果，在投递详情中记录人工核验依据。只有确认操作没有发生才能释放该动作重试；整条投递已由人工完成时，也可单独记录完成依据。

### BOSS 求职端

按“搜索 → 岗位详情 → 规则匹配 → 目标会话 → 按岗位描述生成并发送沟通文案 → 指定附件简历 → 回执核验”执行。发起沟通、补充文案和发送附件分别记录，进入聊天不等于已投递附件。支持两种自动文案：约100字的岗位沟通意向（围绕岗位工作内容，不按简历技能筛选），以及引用简历相关经历的文案。可在岗位详情预览，也可关闭自动生成并填写自定义文案。岗位内容不作为执行指令，不添加未经用户确认的经验陈述。

方案可开启“本轮只发送沟通文案”和“跳过已沟通过的公司与岗位”。发送前结合本地动作记录、平台已有聊天列表及岗位页面的已沟通标记去重；默认同一家公司本轮只沟通一次。发送成功显示“沟通文案已发送”，不计为附件已投递。

新建方案默认每轮搜索 1 页、读取 10 个岗位、最多投递 5 个，并开启历史去重。开启跳过已有沟通后，搜索在打开详情前排除已发送、已沟通、已撤回、无法定位和待核验的公司/岗位。已经读取的公开岗位描述保存在本地数据库；标题和公司未变化时，跨关键词和重启均复用，不重复打开详情。描述以本地上次读取为准；列表标题或公司变化时重新读取，已沟通和待核验对象仍优先跳过。实际发送前重新核对目标岗位和会话。

BOSS 页面跳转至少间隔 15 秒；每次处理后的投递间隔至少 60 秒，即使旧方案保存为 20 秒也会提高到 60 秒。新建主动沟通前还会核对动作账本，确保跨任务和服务重启后保留一分钟间隔。暂停、停止在等待期间仍可生效。岗位描述是公开信息缓存，投递和去重记录按账号隔离。上述设置减少无效访问，不能保证平台不触发限制。

遇到 BOSS 403 地址或“访问受限”提示时，程序停止并显示平台限制原因，不将其当作普通未登录。应等待平台解除限制，再由用户检查状态；不自动刷新、切换账号或重试解除限制。

聊天页支持没有 HR 参数的 `/web/geek/chat` 地址，通过选中会话的头像、姓名、公司及右侧岗位共同核验目标。平台提示“双方回复后可用”时不点击灰色发简历按钮，申请记录显示“等待 HR 回复后发简历”；HR 回复后再次运行该岗位，只继续附件步骤，不重复建联或发送已经核验的文案。

简历选择框中只选择与本地原文件**同名且唯一**的附件。若没有同名附件且弹框提供单一文件上传控件，会上传本地原始文件；如果平台未提供可识别的上传入口，则交由人工处理。平台已有同名附件时，使用前需核对其实际版本，文件名本身不能证明文件字节相同。不能识别目标 HR 或关联岗位时不继续发送。

### 智联求职端

实现职位搜索、详情读取、规则匹配、申请按钮、可识别的确认弹框与已申请状态核验。当前自动任务使用**智联平台当前在线简历**，需要在方案中明确启用；本地 PDF 不代表已经上传到智联。遇到额外问卷、简历选择不明或页面变化时交由人工处理。

## 上传简历后自动求职

上传 PDF、DOCX 或 TXT 后，解析页会自动显示从简历求职意向、技能和项目中提取的搜索方向。已有简历可点击“按简历自动求职”。核对城市与平台城市代码后，点击“开始按简历自动求职”，程序自动串行完成搜索、关联匹配和约100字的岗位意向招呼，无需手填关键词。搜索方向仍从简历原文用本地规则提取；自动求职默认使用大模型做岗位语义匹配与定制招呼，也可明确取消大模型选项使用本地规则。未识别到方向时不自动启动。当前支持 Agent、大模型应用、Python后端、Java和前端方向。

默认厦门、薪资不限、最多3个搜索方向，每个方向只搜索1页、检查最多5个岗位，全部方向合计最多主动沟通5家。城市、薪资和排除词先本地核验；大模型依据简历与岗位职责评估匹配度，达到方案阈值且提供可核验的原文证据后才发招呼。本地模式仍核对岗位方向及共同技术信息；只打招呼，不自动发送附件。现代 BOSS 列表通过点击卡片读取右侧详情；旧版页面才使用独立详情。读取失败不重复点击。沿用公开岗位缓存、历史去重、15秒页面操作间隔、60秒沟通间隔。每个方向完成后再进入下一方向，任何登录、限制、导航或沟通结果未知都会结束整轮任务，不自动恢复，也不自动更换账号或网络。真实账号验收应在平台允许访问后进行；本地模拟测试不能保证实际平台不触发风控。

## 当前验证范围

- 本地 API、数据库并发预占、重启恢复、防重复投递、原简历版本保留已编写自动测试。
- 使用真实 Edge 浏览器和模拟平台页面，验证 BOSS 搜索、沟通、消息、附件回执及智联申请回执；测试不连接真实招聘平台。
- 独立临时数据目录进行五个页面、简历上传与自动读取、方案保存、窄窗口布局验收。
- 真实已登录 BOSS 已验证厦门岗位搜索、详情读取、平台附件管理及目标会话核验；完整附件发送仍取决于平台的双方回复条件。智联尚未进行真实账号验收。模拟测试不能替代真实网站兼容性验证。
- 不实现验证码绕过、隐蔽访问或账号风控规避。自动化接入应遵守平台当前规则和授权范围。
- 大模型支持 Chat Completions 和 Responses 兼容协议。评分与约100字招呼合并为一次请求，并校验 JSON、原文证据及招呼内容。结果按简历、岗位、模型和配置摘要缓存，减少重复调用。超时、HTTP错误、拒绝、截断、无法核验的引用均停止任务，不自动降级或重试。
- 在“设置 → 大模型匹配与招呼”配置接口、模型和密钥。密钥只保存在本地 data 数据库，不回传给前端、不写入任务快照、不提交 Git。留空保存可保留已有密钥。启用后会向所选接口发送经过基础联系方式过滤的简历正文和岗位描述；输入长度有限，超长简历会附带截断标识，不能据此假定缺失内容不存在。
- 模型连接测试只发送合成样例，不发送用户真实简历，也不操作招聘平台。接口 JSON 模式按供应商支持情况配置；无论是否启用接口 JSON 模式，本地都严格验证结果。协议参考 [OpenAI 结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs)。

## 暂停、恢复和去重

- 所有平台操作由同一浏览器工作线程执行，界面通过命令队列调度。实际会话使用按需 CDP DOM/输入命令，不启用 Runtime 事件监听；Playwright 用于隔离的模拟验收。
- 参考招聘端的普通 Edge + 本机 CDP 启动方式。进程启动时直接打开平台网址，重复打开优先复用本项目连接。断开服务不会主动关闭正在登录的 Edge；重连时读取真实标签，避免旧引用一直停在空白页。
- 人工操作平台前点击“暂停 / 人工接管”。不安装操作系统键鼠监听器。
- 恢复发送前核验账号、会话标识、草稿和输入法状态。填写期间发生暂停，会放弃旧发送。
- SQLite 原子预占动作，绑定单次尝试标识；旧回调不能覆盖新尝试。
- 同账号同岗位建立唯一申请；更换简历版本不自动重复投递。
- 发送后超时、崩溃或页面变化进入 `unknown`，不会作为普通失败直接重试。
- 重启后不会自动发送。可以从工作台按原方案快照恢复上一轮中断任务，成功和待核验的动作不会重复执行。
- 账号身份目前根据独立 Profile 和可见账号名称划分；不宣称可唯一识别同名账号，切换账号后须核对当前会话。

本地服务包含请求来源与随机请求令牌校验，令牌由页面自动携带，不是软件账号登录。不要把本地服务端口公开到网络。

## 招呼数量与本地工作空间

在求职方案中设置“成功打招呼多少次后停止”（1–120），也可在“我的简历 → 按简历自动求职”中填写数量。只有平台回执核验成功的招呼计数，已沟通、已撤回和待核验不会重复发送。计数在同一轮的多个搜索方向和平台间共享；达到数量后不再联系下一位。搜索范围用尽、最多处理岗位数达到上限、验证码或其他异常可能提前结束，设定数量不保证一定完成。每次启动为独立的一轮；历史去重仍跨轮保留。BOSS 沟通间隔至少60秒。

在“设置 → 切换本地工作空间”中选择文件夹或填写绝对路径，保存后退出并重启生效。空目录会创建独立工作空间；原简历、数据库、模型配置和登录资料留在原目录。需要保留原数据时，请先退出项目并关闭项目的 Edge 窗口，再完整复制原数据目录到新目录后切换。`SUBMIT_RESUME_DATA` 环境变量优先；设置该变量时页面禁止覆盖目录。路径配置仅存于被 Git 忽略的 `workspace.local.json`。

## 公开仓库与隐私

请勿提交个人简历、数据库、平台登录资料、聊天记录、截图或 API Key。默认 `data/`、`artifacts/`、`.env*`、数据库和本地路径配置均被 Git 忽略。自定义数据目录应放在仓库外。公开仓库前仍应检查所有分支和 Git 历史；`.gitignore` 无法清除已提交过的内容。模型密钥在本地数据库保存，配置接口不回传密钥。


### 沟通回执与故障现场

发送前核对岗位 ID 和来源 HR 身份。点击“立即沟通”后只观察一次操作的结果，不重复发起沟通，也不会接管之前已打开的无关聊天标签。页面没有确认已沟通时，保留原页面；出现平台提示、身份不匹配或结果不明时停止并保留待核验。只有观察到已沟通信号后，才允许通过正常消息中心核对同一位 HR、公司及岗位；已有发出消息的会话不补发。

点击前后的诊断保存在本地 `data/diagnostics/boss-contact-*.json`，记录岗位、HR 身份及可见提示，不记录跳转 URL 中的安全参数。这些文件包含本地求职信息，受 `data/` 忽略规则保护，不应提交到公开仓库。待核验记录不会因升级或重启而清除。


BOSS 当前的职位列表采用滚动加载。“最多搜索页数”同时限制滚动加载批次数，任务会激活自己的平台标签并逐批读取，避免后台标签不触发加载。岗位会记录发现时的搜索页和加载批次，重新定位时按同样范围查找；不会因改写页码参数反复读取首批结果。搜索批次和最多读取岗位数仍是有限上限，不保证能凑满招呼目标。
